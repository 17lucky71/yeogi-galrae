# 04. AI 코딩 도구 사용 기록

이 프로젝트는 AI 코딩 도구 **Claude**(Anthropic)와 대화하며 기획·구현·배포·오류 수정까지 진행했습니다.
아래는 주요 대화 흐름을 정리한 기록입니다. (API 키 값은 대화에 한 번도 붙여넣지 않고, Vercel 설정 화면에 직접 입력했습니다.)

## 1. 기획 단계

| 내가 한 요청 | AI의 응답 / 결과 |
|---|---|
| 과제 설명 전체를 붙여넣고 "다음 과제" 진행 요청 | AI가 먼저 서비스 주제, 사용할 AI API, 보너스 과제 범위를 선택지로 질문 |
| 주제: **AI 여행 코스 추천**, API: **Gemini**, 보너스: **다크 모드** 선택 | 이전 과제(국내 여행지 추천 CLI)와 이어지는 주제로 기획 확정 |
| "무료 사용량을 다 썼으니 GPT로 바꿀까?" 질문 | AI가 Gemini 공식 문서를 확인해 "할당량은 프로젝트·모델별로 따로 계산되고 태평양 시간 자정에 초기화된다"는 점을 확인 → **GPT로 바꾸지 않고, 한 모델이 막히면 다른 무료 모델로 자동 전환**하는 구조로 설계 |
| 기존 GitHub 저장소(Codysseyboy_1) 화면을 보여주며 "이런 README 스타일로" 요청 | 🚀 들어가며 + 📁 문서 링크 목록 형식의 README와 번호 붙인 문서(01~03)로 구성 |

## 2. 구현 단계

- AI가 `index.html` / `css/style.css` / `js/main.js` / `api/recommend.py` 구조로 코드를 작성
- AI가 가짜 AI 응답을 쓰는 테스트 서버를 만들어 **정상 응답, 빈 입력(400), 할당량 초과(429), 형식 오류 재시도, 키 없음(500)** 을 모두 테스트
- 실제 브라우저로 **데스크톱·태블릿·모바일** 화면과 다크 모드를 확인하고, 모바일 햄버거 아이콘 정렬과 필수값 경고 문구가 남는 문제를 수정

## 3. 배포 단계에서 생긴 문제와 해결

| 문제 | 원인 파악 | 해결 |
|---|---|---|
| 압축을 푼 뒤 `git commit` 결과가 9개 파일뿐 | AI가 커밋 목록을 보고 `js/main.js`와 `docs` 문서가 빠진 것을 발견 | 빠진 파일을 다시 넣고 추가 커밋 |
| `git push` 시 `Repository not found` | GitHub에 저장소를 아직 만들지 않음 | 저장소 생성 후 push |
| Vercel이 프로젝트를 **Python** 앱으로 자동 인식 | 이 구조(HTML + api 폴더 함수)는 **Other**가 맞음 | Application Preset을 Other로 변경 |
| 배포 후 AI 버튼을 누르면 "알 수 없는 오류가 발생했어요" | AI가 오류 문구가 코드의 어느 경로에서 나오는지 추적 → 할당량 초과(429) 문구와 다르다는 점을 확인 → 로컬에서 API 키에 **보이지 않는 문자·한글**이 섞였을 때 `UnicodeEncodeError`가 나는 것을 재현 | ① 키 앞뒤 공백 자동 제거 ② 키에 이상한 문자가 있으면 원인을 화면에 안내 ③ 그 외 오류도 오류 종류 이름 표시 + Vercel 로그 기록 ④ AI Studio 복사 버튼으로 키를 다시 입력 → **정상 동작 확인** |
| 결과 화면의 "코스 복사" 버튼 글자가 두 줄로 깨짐 | 제목이 길면 버튼 폭이 줄어듦 | 버튼 글자 줄바꿈 금지 스타일 추가 |

## 4. 배운 점

- AI가 코드를 써주더라도, **오류 문구가 어디서 나오는지 코드에서 거꾸로 따라가면** 원인을 좁힐 수 있다.
- "무료 횟수 초과"처럼 보이는 오류도 실제 문구와 상태 코드를 확인해야 정확한 원인을 알 수 있다.
- API 키는 채팅·코드·스크린샷에 남기지 않고 환경 변수로만 관리해야 한다.
- 로컬에서 되던 것이 배포 환경에서는 설정(환경 변수, 프리셋) 때문에 다르게 동작할 수 있다.
